# 登记卡抽取规则（Agent 执行规范）

> 登记质量决定召回质量。本文件定义「从原文到一条台账记录」的全部判定规则。输出是 JSON，交给 `ledger.mjs register` 入库。

## 一、铁律（违反即作废）

1. **只写原文明确有的内容**。禁止推测、补全、脑补策略和数据。原文没写「ROI 3.2」就不能写 3.2。
2. **`原文摘录` 必须原样摘抄**，不改写、不润色、不拼接。无依据时留空字符串。
3. **不确定的一律标「待确认」**，并勾 `待人工确认`、把原值写进 `备注`。宁可让人审一次，不要写错口径污染台账。
4. **绝不编造链接**。资料没给链接就留空，把 `载体类型` 设为「纯文本段落」或「本地文件」，如实标 `可读状态`。
5. **不迁移、不复制、不修改原始资料**。台账只存索引 + 结构化成果。
6. **一份资料含多个复盘要拆条**。例如一份季度报告里写了 7 月和 8 月两次活动复盘 → 拆成两条，各自填自己的 `覆盖周期` 和内容。

## 二、每条必填 / 可空

| 必填 | 可空（但要如实标状态） |
|---|---|
| 复盘标题、项目标准名、覆盖周期、载体类型、资料归属、可读状态、内容摘要、置信度、登记来源、解析状态 | 周期间界、提交日期、所有分类标签（空→待确认）、链接/路径、D 组各项（读不到就留空并在备注说明） |

`检索键`、`来源指纹` 由脚本生成，**不要填**。`登记时间`、`最后变更` 是系统字段，**不要填**。

## 三、分类判定规则（含正反例）

### 复盘类型
- 营销复盘：投放、Campaign、活动、内容种草、电商大促、详情页/SEO/GEO 效果、社媒运营、上市项目
  - 正例：「618 京东首发投放复盘」→ 营销复盘
  - 反例：「618 期间团队排班与协作问题总结」→ 日常工作复盘
- 日常工作复盘：流程、协作、例会、日常运营、项目管理的执行总结
- 边界：以**复盘主体**判断，不以文档所在文件夹或提交人部门判断。判断不了 → 待确认

### 复盘范围（复盘对象，不是资料密级）
- 内部复盘：复盘我方团队、我方项目、我方执行动作
  - 正例：服务商 Digishare 写的「我方北美 AEO 试点复盘」→ 仍是**内部复盘**（对象是我方项目）
- 外部复盘：复盘市场、竞品、行业、外部合作方自身表现
  - 正例：「安吉尔 T7 Pro 上市动作拆解」→ 外部复盘
- 两者都有 → 内外部结合

### 产出方类型
- 自己团队 / 服务商 / 混合 / 其他 / 待确认
- 与 `复盘范围` **独立判断**，不要因为「服务商写的」就填「外部复盘」

### 归属BU / 市场区域 / 涉及平台
- 以复盘覆盖的业务与市场为准，不以提交人所属组织为准
- 平台只在原文明确提及时勾选；「全渠道」「线上为主」这类泛称写进 `备注`
- 跨 BU → 跨BU/集团；国内+海外 → 全球

### 覆盖周期（最容易填错）
- 填**复盘覆盖的业务周期**，不是成文日期
- 「8 月复盘，9 月 3 日成文」→ 覆盖周期「2026年8月」，复盘提交日期「2026-09-03」
- 原文没给年份 → 用上下文推断并在 `备注` 说明推断依据；推断不了 → 「待确认」+ 勾人工确认，**禁止默认当年**

## 四、置信度评分

| 区间 | 条件 |
|---|---|
| 0.90–1.00 | 已读全文，分类与策略均原文明确，链接可回源 |
| 0.75–0.89 | 已读全文，个别字段靠上下文推断 |
| 0.60–0.74 | 仅读到摘要/部分章节，或存在 1–2 个待确认字段 |
| < 0.60 | 未读原文，仅凭转述/标题登记 |

**< 0.7 必须勾 `待人工确认`**。任何自动抽取结果都不允许标 1.0（保留人工判断空间）。

## 六、常见错误自查

- [ ] 把「9 月成文」误填进「覆盖周期」
- [ ] 同一项目写成多种名字（I2 PRO / i2pro / I2Pro）
- [ ] 服务商写的复盘被误判为「外部复盘」
- [ ] 把泛称「全渠道」勾成全部平台
- [ ] 链接读不通却标「可直接读取」
- [ ] `核心策略` 写成一段散文而不是编号条目（内容召回时不好用）
- [ ] `原文摘录` 被改写成自己的话
- [ ] 一份资料含多次复盘却只登记了一条
